Stemma는 쓴 글을 고쳐 쓰는 사람을 위한 글쓰기 도구이며, 내 컴퓨터 안에서만
실행됩니다. 지금까지 쓴 글을 개인 아카이브에 보관하고, 그 안에서 옛 글을 찾고,
그 글을 이어받는 새 글을 쓰고, 직접 고른 판본을 한국어와 영어로 짝지어 정적
블로그에 발행합니다. 옛 글에서 새 글로 이어지는 계보는 그대로 보존되며,
원한다면 독자에게도 공개할 수 있습니다.

모든 작업은 내 컴퓨터에서 이루어집니다. 직접 배포하기로 선택한 정적 사이트를
제외하면, 어떤 자료도 외부로 전송되지 않습니다.

> *stemma codicum*은 어떤 사본이 어떤 사본에서 갈라져 나왔는지 보이기 위해
> 문헌학자들이 그리는 계통도입니다. 이 도구는 그 계통도를 내가 쓴 글에 대해
> 만들어 줍니다.

## 이 문서에 대하여

프로그램 화면은 한국어와 영어 가운데 하나로 볼 수 있으며, 위쪽 막대에서 언어를
바꿀 수 있습니다. 문서와 코드, 명령줄은 영어로 되어 있습니다. 발행되는 사이트는
한국어 판본과 영어 판본을 짝지은 형태입니다. 한국어로 쓰고 영어로 옮길 수도 있고,
영어로 쓰고 한국어로 옮길 수도 있습니다.

이 문서는 사용을 시작하는 데 필요한 내용만 담은 짧은 안내문입니다. 자세한
설명은 아래에 정리해 둔 영어 문서에 모두 들어 있습니다.

> **영어 문서는 Claude를 비롯한 AI 도구로 읽으시기를 권합니다.** 문서는 모두 이
> 저장소 안에 들어 있는 평범한 Markdown 파일이므로, 파일 내용을 그대로 복사해서
> 붙여 넣고 번역이나 요약을 요청하면 됩니다. 한국어 번역본을 따로 두지 않는
> 이유는, 번역본이 원문보다 먼저 낡아 버리기 때문입니다.

## 무엇이 다른가

대부분의 블로그 도구는 글 하나를 그 자체로 완결된 결과물로 취급합니다. 반면
Stemma는 글을 **이어받은 것**으로 취급합니다. 이 글이 저 글에서 나왔고 특정한
물음에 답하기 위해 쓰였다는 관계를, 부가 정보가 아니라 일급 데이터로
저장합니다.

- **물음**(question)은 내가 묻고 있는 내용입니다. 글 하나는 물음 하나 이상에
  속합니다.
- **계승 간선**(succession edge)은 한 글이 다른 글에서 나왔다는 사실을
  기록합니다.
- **판본**(revision)은 한 번 저장하면 바뀌지 않습니다. 글을 고쳐 써도 이전에 쓴
  판본을 덮어쓰지 않습니다.
- **발행 짝**(publication pair)은 검토를 마친 한국어 판본과 영어 판본 한 쌍을
  뜻합니다. 발행할 때는 이 짝을 발행하며, 판본 하나만 따로 발행하지는 않습니다.
- **계보**(genealogy)는 이렇게 쌓인 관계가 이루는 그래프이며, 발행된 사이트에서
  독자가 직접 따라가 볼 수 있습니다.

## 요구사항

- **Python 3.12 이상이 필요합니다.** 핵심 모듈과 편집기, 블로그는 표준
  라이브러리만 사용합니다.
- **Node.js는 수식이 들어간 글을 발행할 때만 필요합니다.** KaTeX가 빌드 시점에
  수식을 정적 MathML로 변환하기 때문에, 독자의 브라우저에서는 실행되지 않습니다.
- **Git은 Git 아카이브에서 글을 가져오거나 풀 리퀘스트로 배포할 때만
  필요합니다.** 폴더로 발행하는 경우에는 Node.js와 Git이 모두 없어도 됩니다.

## 설치

Stemma는 PyPI에 [`stemma-studio`](https://pypi.org/project/stemma-studio/)라는
이름으로 올라가 있습니다. 설치하면 [`stemma-graph`](https://pypi.org/project/stemma-graph/)도
함께 설치됩니다. Stemma는 명령어로 실행하는 프로그램이므로, 프로그램마다 별도의
환경을 만들어 주는 [pipx](https://pipx.pypa.io/)로 설치하는 방법이 가장 간단합니다.

```sh
pipx install --python python3.12 stemma-studio
```

위 명령을 실행하면 `stemma` 명령을 사용할 수 있습니다. 새 버전이 나오면
`pipx upgrade stemma-studio`로 업데이트합니다. 가상환경을 직접 만들어 설치해도
됩니다.

```sh
python3.12 -m venv ~/.venvs/stemma
~/.venvs/stemma/bin/pip install stemma-studio   # 명령은 ~/.venvs/stemma/bin/stemma
```

macOS에서 Homebrew로 설치한 Python에 `pip install`을 바로 실행하면
`externally-managed-environment` 오류가 납니다. 이 경우에는 위의 두 방법 중
하나를 사용합니다.

## 시작하기

```sh
mkdir my-writing && cd my-writing
stemma init                      # 이 폴더에 data/studio.json을 만듭니다
stemma editor                    # http://127.0.0.1:8787
```

`init`은 명령을 실행한 폴더에 빈 데이터 루트를 만듭니다. 데이터를 다른 위치에
두고 싶다면 모든 명령이 `--root` 옵션을 받습니다. 이 옵션을 주지 않으면 현재
작업 폴더가 데이터 루트가 됩니다.

아직 쓴 글이 없더라도 발행된 사이트가 어떤 모습인지 미리 보고 싶다면 다음
명령을 실행하면 됩니다.

```sh
stemma preview
```

그다음 브라우저에서 <http://127.0.0.1:8766/blog/> 주소를 엽니다. 이 명령은 예시
데이터를 메모리에 올려서 보여 줄 뿐이며, 디스크에는 아무것도 쓰지 않습니다.

## 작업 흐름

모든 과정은 로컬 서버 한 대 위에서 네 단계로 진행됩니다.

| | 단계 | 어디서 |
|---|---|---|
| 1 | **블로그를 설정합니다**: 블로그 이름, 글쓴이 이름, 글을 쓰는 언어, 내 글에 적용할 라이선스를 정합니다 | 설정 화면 `/publish/?view=settings` |
| 2 | **이미 쓴 글을 가져온 다음, 새 글을 씁니다** | 가져오기 화면을 거쳐 편집기 `/` |
| 3 | **발행합니다**: 번역 판본을 붙이고, 짝을 검토하고, 확정합니다 | 발행 화면 `/publish/` |
| 4 | **배포합니다**: 사이트를 폴더에 쓰거나, 풀 리퀘스트를 하나 엽니다 | 사이트 화면 `/publish/?view=site` |

1단계를 가장 먼저 해 두시기를 권합니다. 설정을 마치기 전까지는 페이지가 임시
이름으로 발행되고, 내 글에는 기본값인 '모든 권리 보유' 조건이 적용되기
때문입니다. 새로 만든 데이터 루트에서는 글을 쓰는 언어를 정하기 전까지 발행할
수 없습니다. 이 언어로 쓴 판본이 원문이 되고, 다른 언어가 번역이 됩니다.

가져오기 기능은 읽기 전용입니다. 지정한 폴더를 읽기만 할 뿐 고치지 않으며,
저장하기 전에 무엇을 가져올지 먼저 보여 줍니다. 그림 링크는 고쳐 쓰지 않기
때문에, `![](images/cat.png)`처럼 상대 경로로 적어 둔 링크가 그대로 동작합니다.

## 상태

이 도구는 한 사람이 자기가 쓰려고 만든 것을, 다른 분들께도 쓸모가 있을까 하여
공개한 결과물입니다. 로컬 작성자가 한 명이라고 가정하며, 그 가정을 프로그램이
강제하지는 않습니다. 서버 한 대는 자기에게 들어온 요청을 차례대로 처리하지만,
서버 두 대 사이나 서버와 명령줄 사이를 맞춰 주는 장치는 없습니다. 따라서 데이터
루트 하나에 두 개를 동시에 실행하지 마세요.
